스케줄

주기 실행의 경계

(scheduled_for, trigger_type)가 멱등 경계다. 같은 스케줄로 두 번 돌려도 브리핑은 하나이고 전달도 한 번이다. 이미 처리된 문서는 다시 분류하지 않고 skip으로 집계한다.

실패 처리

실패는 감추지 않는다

한 문서의 실패가 사이클을 멈추지 않는다. 실패는 alerts/ 아티팩트와 요약의 failures에 남고, 시크릿과 원문 전문은 마스킹된다. 실패 알림은 브리핑 전달 채널과 분리돼 있다.

관측

지표는 항상 남는다

브리핑·게이트·전달이 실패해도 지표 6종 계산, 리포트 아카이브, 위반 알림은 수행된다. 현재 M3·M5는 목표 충족, 나머지 넷은 표본 부족이며 이는 충족으로 바뀌지 않는다.

운영자가 실제로 쓰는 경로

사이클은 후보도 브리핑도 자동 승인하지 않는다. 전달까지 가려면 사람의 결정이 두 번 들어간다.

  • 수집과 후보 정리 한 번 실행하면 수집부터 지표·리포트·알림까지 끝난다. 브리핑은 승인 대기 상태로 남는다. make run-briefing-cycle
  • 후보 검토와 승인 검토 큐에서 후보를 확인하고 승인·반려한다. 경계 점수나 낮은 신뢰도는 계속 검토 대기로 남는다. review-cli list --status needs_review · decide <id> --decision approved
  • 브리핑 발행 승인과 전달 승인 항목을 담아 다시 만든 브리핑을 운영자가 발행 승인한 뒤 dry-run으로 전달한다. 전달은 다시 빌드하지 않는다. review-cli briefing-decide <id> --decision approved · briefing-deliver <id>

남은 작업

코드로 풀 수 있는 것과 사람이 결정해야 하는 것을 분리했다. 자세한 근거는 docs/open-work.md에 있다.

지금 유일하게 막혀 있는 것 — 다중 주장 후보의 전달

핵심 필드를 2개 넘게 주장하는 후보가 든 브리핑은 아직 전달할 수 없다. 두 요구가 동시에 만족되지 않는다.

  • 렌더러는 주장하는 필드마다 근거를 요구한다.
  • 발행 게이트는 브리핑 항목 하나당 근거 최대 2건만 허용한다.

근거를 2건만 실으면 나머지 주장에서 “근거 없음”, 후보의 근거 6건을 모두 실으면 “2건 초과”가 난다. 둘 다 실행으로 확인했다. 해결안 세 가지(상한을 필드별로 적용 / 전달 payload를 필드별 구조로 변경 / 전달 메시지에서 필드별 근거 요구 제외)는 모두 발행 콘텐츠 경계에 닿으므로 결정이 필요하다.

관찰되는 현상 이유
기본 실행이 게이트에서 멈추고 종료 코드 1 승인되지 않은 브리핑은 발행하지 않는다. 부분 성공을 성공으로 보고하지 않는다.
재실행 시 문서 대부분이 skip 이미 처리를 마친 문서 버전은 다시 분류하지 않는다. 실패가 아니라 반복하지 않은 일이다.
지표 대부분이 표본 부족 관측 창 하나에는 표본이 없다. 표본 없음을 충족으로 바꾸지 않는다.
브리핑을 다시 빌드하면 승인이 풀림 다시 빌드한 내용은 운영자가 승인한 그 내용이 아니다.
